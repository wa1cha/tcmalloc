  ## 过程中发现并修复的 bug（按排查顺序）                                                                                                                   
                                                                                                                                                            
  ### 1. ObjectPool::New() 的 objsize 算错 —— 首次分配崩溃                                                                                                  
  - 现象：`NewSpan` 里 `_spanLists[nSpan->_n]` 越界，`nSpan->_n` 是野值 17179852143（≈2^34）
  - 定位：gdb 打印 `nSpan->_n`、`nSpan->_pageId` 发现两者差 2，正好是 kSpan 覆盖 nSpan 字段的量                                                             
  - 原因：`objsize = max(sizeof(T*), sizeof(void*))` = 8，但 Span 实际 64 字节。池子每次只前进 8 字节，导致 kSpan 和 nSpan 重叠 56 字节，`kSpan->_n = k` 把 
  nSpan 的 `_n` 覆盖掉了                                                                                                                                    
  - 修复：`objsize = std::max(sizeof(T), sizeof(void*))`                                                                                                    
                                                                                                                                                            
  ### 2. ObjectPool::New() free-list 分支 off-by-one                                                                                                        
  - 原因：`obj = NextObj(_freeList)` 跳过了 free-list 第一块                                                                                                
  - 修复：`obj = _freeList; _freeList = NextObj(_freeList);`                                                                                                
                                                                                                                                                            
  ### 3. FreeList::PopRange 方向写反 —— 释放阶段段错误                                                                                                      
  - 现象：`Deallocate → ListTooLong → PopRange` 在 `end=NextObj(end)` 崩，start/end 都是 0                                                                  
  - 原因：`_freelist = start` 把链头赋成 null（start 是入参为 null 的出参），应反过来 `start = _freelist`                                                   
  - 修复：`start = _freelist;`                                                                                                                              
                                                                                                                                                            
  ### 4. FetchRangeObj 的 _useCount 符号反了                                                                                                                
  - 原因：`span->_useCount -= actNum`，切出去应该加                                                                                                         
  - 修复：`+= actNum`                                                                                                                                       
  - 后果若不修：useCount 永远非 0，span 永不归还 PageCache，内存泄漏                                                                                        
                                                                                                                                                            
  ### 5. ReleaseListToSpans 漏解锁 —— 死锁（挂起）                                                                                                          
  - 现象：第二次进 ReleaseListToSpans 卡在 `futex_wait`（`_spanLists[index]._mtx.lock()` 等不到锁）                                                         
  - 定位：gdb `bt` 看到主线程卡在 ReleaseListToSpans:50                                                                                                     
  - 原因：函数开头 lock 了桶锁，结尾没有 unlock                                                                                                             
  - 修复：函数末尾补 `_spanLists[index]._mtx.unlock();`                                                                                                     
  - 同函数：`span->_prev==nullptr;` 应为 `span->_prev=nullptr;`（== 是无操作）                                                                              
                                                                                                                                                            
  ### 6. Deallocate 的阈值                                                                                                                                  
  - `Size() > MaxSize()` 应为 `>=`，到点就归还，避免内存滞留                                                                                                
                                                                                                                                                            
  ## 经验总结                                                                                                                                               
  1. 野值（如 17179852143 ≈ 2^34）几乎都是"字段没初始化"或"内存被别的对象覆盖"                                                                              
  2. gdb 排查套路：`bt` 看调用链 → 到对应帧 `p 关键变量` → 对比合理性                                                                                       
  3. 手写内存池最容易错的三类：对象大小/对齐、链表方向、锁的成对性                                                                                          
  4. 每把锁的 lock/unlock 必须覆盖所有返回路径
